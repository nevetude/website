# ADR 0001: ORM

Status: **accepted** (2026-10-11): PostgreSQL + SQLAlchemy 2.0 (async) + Alembic + separate Pydantic v2 schemas.

## Context

The domain is relational and rich: artists, releases, tracks, many-to-many credits with roles, genre hierarchy, ratings, reviews, playlists, full-text search, polymorphic annotations. SQLModel is pre-1.0 (Beta) and pushes to raw SQLAlchemy for CTEs, aggregates, JSONB/ARRAY columns, polymorphism and association objects. Its main benefit (one class for table and schema) disappears when API shapes differ from tables, which is typical for catalog pages.

## Decision

- SQLAlchemy 2.0 with typed `Mapped[]` / `mapped_column`, async engine and sessions. Keep models compact with `MappedAsDataclass` where it fits.
- Pydantic v2 schemas for I/O (`from_attributes=True` for reads, small `Create`/`Update` schemas for writes).
- PostgreSQL only, run via Docker Compose. SQLite is rejected: search (`pg_trgm`, `unaccent`, `tsvector`), JSONB/ARRAY, and migrations (`ALTER TABLE`) make it a dialect we would have to rewrite away from.
- Alembic for migrations.
